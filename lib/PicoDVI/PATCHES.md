# Local changes to vendored PicoDVI

Upstream: https://github.com/Wren6991/PicoDVI, commit `dccd738` (2026-08-01).
Only `software/libdvi/` is vendored, as `src/`. Upstream's `LICENSE` is kept.

## 1. 64-bit pin masks in the serialiser (`pio/dvi_serialiser.pio`)

On the Waveshare RP2350-PiZero (RP2350B), the TMDS pairs sit on
GPIO 32–39. `pio_sm_set_pins_with_mask()` and
`pio_sm_set_pindirs_with_mask()` take 32-bit masks, so `3u << 36`
overflows and the pins are never driven. Both calls are replaced with the
pico-sdk 2.x `*_with_mask64()` variants. The caller (`hal/video.c`) must
also call `pio_set_gpio_base(pio, 16)` before `dvi_init()`, so that the PIO
block can address GPIO 16–47.

## 2. Pre-generated PIO header

PlatformIO does not run `pioasm`, so `src/dvi_serialiser.pio.h` is
generated by hand and checked in. To regenerate it after editing
`pio/dvi_serialiser.pio`:

    ~/.platformio/packages/tool-pioasm-rp2040-earlephilhower/pioasm \
        pio/dvi_serialiser.pio src/dvi_serialiser.pio.h

`tmds_encode_1bpp.pio` was dropped because nothing includes it.

## 4. Precompute the control-channel DMA config (`dvi.c`, `dvi_timing.h`)

`_dvi_load_dma_op()` runs in the DMA IRQ on every scanline and called
`dma_channel_get_default_config()`. GCC out-lined that function into
flash. The config is constant per lane, so `dvi_init()` now computes it
once into `struct dvi_lane_dma_cfg.ctrl_cfg`, and the IRQ path copies
it. Register values are unchanged.
